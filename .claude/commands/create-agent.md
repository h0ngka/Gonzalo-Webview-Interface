새 서브에이전트를 만드는 대화형 마법사를 시작하세요. AskUserQuestion 도구를 사용해 아래 단계를 **순서대로** 진행하세요. 사용자가 `$ARGUMENTS`로 힌트를 주었다면 참고하되, 여전히 각 단계를 확인 질문으로 물어보세요.

1. **저장 범위**: 이 프로젝트에만 (`.claude/agents/`) 인지, 모든 프로젝트 (`~/.claude/agents/`) 인지 질문.
2. **역할/목적**: 이 서브에이전트가 어떤 작업을 담당하는지 질문 (예: 코드 리뷰, 테스트 작성, 리서치/탐색 등). "직접 설명할게요" 옵션도 제공.
3. **도구 접근권**: "모든 도구", "코드 읽기/쓰기만 (Bash·브라우저 자동화 제외)", "직접 지정" 중 선택.
4. **호출 방식**: "수동 호출만" 또는 "자동 호출(proactive)" 중 선택.
5. **배경색**: 다른 단계와 동일하게 AskUserQuestion으로 반드시 질문. red / blue / green / yellow / magenta / cyan 6개를 옵션으로 제시하고, 각 옵션의 `description`에 "터미널에서 이 에이전트가 실행될 때 표시되는 배경색" 정도로 설명을 붙이세요. 건너뛰지 말고 항상 물어보세요.

모든 답변을 받으면:
- 답변을 바탕으로 서브에이전트 이름(kebab-case)을 정하세요 (역할에서 자연스럽게 추론하거나 필요하면 다시 질문).
- 저장 범위에 맞는 디렉터리(`.claude/agents/` 또는 `~/.claude/agents/`)가 없으면 생성하세요.
- 아래 형식으로 `<agent-name>.md` 파일을 작성하세요:

```markdown
---
name: <agent-name>
description: <역할 요약 + proactive 트리거 문구(자동 호출을 선택한 경우)>
tools: <선택한 도구 목록 또는 *>
color: <선택한 색상>
---

<시스템 프롬프트: 역할, 담당 영역, 작업 시 유의사항을 한국어로 구체적으로 작성>
```

- 마지막으로 생성된 파일 경로와 핵심 설정(범위, 도구, 호출 방식, 색상)을 한국어로 짧게 요약해 사용자에게 보고하세요.
